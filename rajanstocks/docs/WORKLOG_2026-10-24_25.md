# Day 2 (late, 2026-10-24): the stuck loader — root cause found and fixed

## The bug that mattered
**The app was stuck on "Loading live NSE data…" for everyone, on every device, on every reload.**
All earlier boot-hardening (timeout races, try/catch) never got a chance to run — the crash
happened before the boot code executed.

Root cause (one eager call, three cascading failures):
1. The PWA install-button code in the notifications script block (block B, lines 1382-1865)
   called `pwaRefresh()` at load time. `pwaRefresh` renders the button icon via `I('download',17)`
   — but `I` is a `const` defined in the main script block (block C, line 1903), which runs AFTER
   block B. → `ReferenceError: I is not defined` — **block B aborted mid-way**, so
   `global.RN = {...}` (line 1862) never ran.
2. Block C then started and died at `RN.init({...})` (line 4508) with
   `ReferenceError: RN is not defined` — **the boot sequence never ran** → loader forever.
3. Both blocks had been dying since the PWA button was added. Every other symptom seen that day
   (blank tabs, no charts, "nothing works") was this one error.

## The fix (commit 0ecfc83, live as 2026-10-24-post-0ecfc833)
- `pwaRefresh()` no longer touches `I` until it exists:
  `try{if(typeof I!=='undefined')b.innerHTML=I('download',17)}catch(e){}` — the eager call only
  sets button visibility; the icon is drawn later by boot's own `$('#pwaBtn').innerHTML=I(...)`.
- `global.pwaRefresh=pwaRefresh;` inside block B's IIFE — the main block's `boot()` calls it, and
  it was private to the IIFE before (would have been the *next* error after the first was fixed).

## How it was verified (local reproduction, then live)
- Reproduced the exact live failure with a headless-Chromium boot check:
  `pageerror: I is not defined` + `RN is not defined`, body stuck at 48 chars of text.
- Fixed → local proxy server (serves the edited `static/index.html`, proxies `/api/*` to
  production) → boot completes in ~6s, all 8 tabs render, zero page errors.
- Pushed to `rajan-web-session`, waited for the Vercel build (`cache-version` shows
  `2026-10-24-post-0ecfc833`), re-ran the boot check against production:
  desktop (Trade tab renders, 9.9k chars of content) and mobile 390px Android UA
  (install button visible with icon) — **zero page errors in both**.

1. **The gap + "Below 65% strength" text floating mid-grid on desktop**: `.pk-div{grid-column:1/-1}`
   was defined INSIDE `@media (max-width:900px)` — on desktop the divider took a single grid cell
   (text stuck in the top row, rest of the row empty). Moved to global CSS next to `.pk-grid`.
   Verified: divider width == grid width at 1440px.
2. **`Cannot read properties of undefined (reading 'last')` on every Picks render**:
   `liveUpdate`'s `data-chg`/`data-chga` handlers had no missing-symbol guard (`data-px` did).
   Today's payload includes the newly added indices (SENSEX, BANKEX, …) that the frontend NAME map
   lacks → `SYM()` returned undefined → TypeError killed the rest of the price-update pass each
   render. Fixed with guards + renderPicks now registers ANY payload symbol missing from NAME
   (index picks included) so their price/chg render at all.

   was stalled because the earlier `bhav:sessions` clobber left the store under the 25-session

   memory TTL for picks was 3600s on a closed day, so instances served hour-old copies of the
   advancing shared payload — reduced to 240s (build_ok still reads the shared store first, so
   rebuilds stay cheap). Cash empty state now says the scan progresses through the day instead of
   a bare "no match".

## Global chart history + watchlist clipping (user report, fixed, live)

1. **"Incomplete data in charts after certain time" (GIFT Nifty 10m)**: the backend feed was fine
   (probed `/api/m/gcandles` — 2,205 bars through Oct 24 02:25, gaps only weekends). The frontend
   `tvCount()` computed bars-per-day from NSE's 6.25-hour session (22500s → 37.5 bars/day) for ALL
   instruments — GIFT Nifty trades ~21h/day (~126 10m bars), so any selected range loaded a third
   of the real window and the chart looked like it "ran out". Fixed with `TV_SESS(id)`: GIFT
   futures 76500s, crypto 86400s, everything else 22500s. Verified: 10m chart now loads 2,506
   bars spanning 31.8 days continuously. Note: the TradingView free feed caps a request at 5,000
   bars, so 10m GIFT ranges beyond ~40 days still compress — inherent feed limit, not a bug.
2. **Frozen-history hardening**: `refreshGlobalChart` (60s refetch) stamped its timestamp BEFORE
   the fetch, so a failed fetch froze history for a minute; now a failure retries in ~15s.
3. **Watchlist rows clipped on the right** (prices cut mid-digit on stocks): `.wl-row` grid used
   `1fr` whose min-content floor (unbreakable tickers like HDFCBANK) forced the row wider than the
   panel, clipping the price column. Fixed: `minmax(0,1fr)` + ticker ellipsis + `white-space:nowrap`
   on the price column. Verified 0 clipped rows.
